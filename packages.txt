# Khadi — package manifest. Phase 1.
#
# Official Arch repos only. Nothing here may come from the AUR: Khadi ships as
# a pacman repo and a repo cannot depend on the AUR (PLAN.md section 7).
# Lines are "package  # why". Blank lines and # comments are ignored.

# --- session -----------------------------------------------------------
hyprland           # compositor; locked Phase 0
foot               # terminal; locked Phase 0 (CPU-rendered, tunable box strokes)
zellij             # panes; does layout, not looks
fuzzel             # launcher, Wayland-native
mako               # notifications
gtk4               # khadi-bar runtime. waybar used GTK3, so this is new.
gtk4-layer-shell   # the layer-shell protocol binding khadi-bar needs
hyprlock           # lock screen
greetd             # login daemon
greetd-tuigreet    # TUI greeter — a text-mode login matches the aesthetic
plymouth           # the boot splash. PLAN.md section 8: the first impression
                   # starts at boot, not after reboot. Installed by the
                   # separate `khadi-boot`, which needs root.
libnotify          # notify-send; a desktop without it is incomplete
grim               # screenshot
slurp              # region select
wl-clipboard       # clipboard

# --- GUI apps ----------------------------------------------------------
# Khadi is terminal-FIRST, not terminal-only. A portal is how a GUI app asks
# the desktop to open a file or share a screen, and BOTH backends are needed:
# read from the installed .portal files, hyprland's implements Screenshot,
# ScreenCast, GlobalShortcuts and InputCapture — and not FileChooser, which
# is gtk's. Installing only the Hyprland one is the obvious mistake and it
# leaves you with screen sharing and no file picker.
xdg-desktop-portal          # the frontend every GUI app talks to
xdg-desktop-portal-hyprland # screencast, screenshot, global shortcuts
xdg-desktop-portal-gtk      # file chooser, print, settings (colour scheme)
dbus                        # the portal is D-Bus activated, and the session's
                            # dbus-update-activation-environment is from here.
                            # Nothing in the manifest depended on it directly.
glib2                       # gsettings, which is how the colour scheme is set
chromium                    # what Super+B launches. The keybind already
                            # committed to it; the manifest now says so.

# --- workspace ---------------------------------------------------------
btop               # system panels; see the measured width minimums in PLAN.md
yazi               # file browser
helix              # editor — pending the Phase 1 open decision vs neovim
git
fish               # not the login shell; interactive default only
starship           # the prompt (A/B item 13). Cross-shell, because Khadi does
                   # not own the login shell and a fish-only prompt would be
                   # absent for most users on the day they install.

# --- fonts -------------------------------------------------------------
# Rajdhani and Orbitron are NOT in the official repos and are vendored by

# 2-face subset. See PLAN.md section 3.
ttc-iosevka        # 446 MiB — TEMPORARY, Phase 4 vendors a subset
